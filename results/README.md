# results/

Сирі виходи моделі з усіх прогонів. Комітяться навмисно: усі цифри в
документації беруться звідси, і їх можна перевірити без API-ключа.

## Зведені звіти

| Файл | Що показує | Породжується |
|---|---|---|
| `model_comparison.md` | Haiku vs Sonnet vs Opus: якість, латентність, вартість | `scripts/compare_models.py` |
| `eval_prompts.md` | V1 vs V2 vs V3 на тому самому наборі | `scripts/eval_prompts.py` |
| `stability_v3.md` | повторюваність V3 на трьох прогонах | `scripts/stability_check.py` |

## Окремі прогони

`run_<версія промпту>[_<тег>]_<дата-час>.{json,md}` — `.md` для читання,
`.json` з повними виходами моделі, токенами й латентністю по кожному тікету.

Актуальні: останній прогін кожної версії промпту (`run_v1_eval_*`,
`run_v2_eval_*`, `run_v3_eval_*`), кожної моделі (`run_v3_haiku-4-5_*`,
`run_v3_sonnet-5_*`, `run_v3_opus-5_*`) і останній прогін датасету
(`run_v3_2026*`).

## Збережені навмисно

Два прогони лежать під власними іменами, бо на них посилається документація —
це докази, а не історія:

| Файл | Навіщо |
|---|---|
| `run_v2_first_run_tone_bias.json` | V2 знижує пріоритет T15 через ввічливий тон: «it's not urgent per their own note». `docs/edge-cases.md`, випадок 1 |
| `run_v3_draft_before_rule_fix.json` | чернетка V3 до виправлення двох правил пріоритету (T09, T13). `docs/prompt-evolution.md` |
