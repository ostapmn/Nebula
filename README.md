# Nebula — AI-класифікатор звернень підтримки

Прототип системи, яка приймає текст тікета і повертає **категорію**, **пріоритет**
і **рекомендований наступний крок** — плюс рішення про те, чи можна цей тікет
обробляти без людини.

Тестове завдання на позицію AI Ops Specialist.

---

## Швидкий старт

```bash
python3 -m venv .venv && .venv/bin/pip install -r requirements.txt
cp .env.example .env    # вписати ANTHROPIC_API_KEY
```

Один тікет:

```bash
.venv/bin/python -m nebula_triage.cli "My subscription renewed and I want my money back"
```

```
category      : refund_request
priority      : P1
next step     : route_to_refunds_review
handling      : HUMAN REVIEW REQUIRED
sentiment     : frustrated   confidence: 0.85   language: en
reasoning     : User explicitly requests a refund for an unwanted auto-renewal charge.
policy rules  : refund_needs_human
  -> refund decisions are made by a person, never by the model
```

Весь набір із 15 тікетів:

```bash
.venv/bin/python -m nebula_triage.cli --dataset data/tickets.json
```

Порівняння трьох поколінь промпту (~$0.26, 45 викликів):

```bash
.venv/bin/python scripts/eval_prompts.py
```

Детерміністичний шар — **без ключа й без мережі**:

```bash
.venv/bin/python scripts/test_policy.py
```

Подивитись сам промпт (V2 і V3 збираються з `taxonomy.py`, тож у файлі лежить
шаблон, а не фінальний текст):

```bash
.venv/bin/python -m nebula_triage.cli --show-prompt --version v3
```

## Результати

`claude-sonnet-5`, 15 тікетів (7 із них — edge cases), прогін 2026-09-07:

| метрика | V1 наївний | V2 зі схемою | V3 фінальний |
|---|---|---|---|
| точність категорії | 7% | 100% | 100% |
| точність пріоритету | 40% | 100% | 100% |
| точність review-гейта | 33% | 93% | 93% |
| safety recall | **0%** | 100% | 100% |
| стійкість до prompt injection | так | так | так |
| виходів поза схемою | **29** | 0 | 0 |
| вартість прогону | $0.046 | $0.073 | $0.140 |

Стабільність V3 на трьох повторних прогонах (`scripts/stability_check.py`):
**11/15 тікетів ідентичні**, пріоритет 100% у кожному прогоні, safety recall 100%
у кожному прогоні. Там, де ярлик пливе, маршрут усе одно лишається тим самим —
це і є причина, чому рішення ухвалює код, а не модель.

> 15 синтетичних тікетів, розмічених одним автором, — це доказ працездатності
> підходу, а не оцінка якості. Що саме цей вимір не доводить — в кінці
> `docs/prompt-evolution.md`.

## Як це працює

```
текст тікета
   │
   ├─ 1. НОРМАЛІЗАЦІЯ — текст загортається в <ticket>…</ticket> як дані, не команди
   │
   ├─ 2. LLM  ← єдине місце, де працює AI
   │     claude-sonnet-5, системний промпт V3, відповідь через messages.parse()
   │     зі схемою Pydantic: category · secondary_categories · priority ·
   │     sentiment · confidence · language · safety_signal · action · reasoning
   │
   ├─ 3. ВАЛІДАЦІЯ — значення поза словником неможливе на рівні API
   │
   ├─ 4. POLICY  ← звичайний код, без AI; може лише підвищити обережність
   │     safety-сигнал        → людина, P0, крапка
   │     рефанд               → людина, мінімум P1
   │     кілька тем           → людина
   │     confidence < 0.75    → людина
   │     агресія + шаблон     → людина
   │
   └─ 5. МАРШРУТ у чергу команди, або прапорець на review-чергу з причиною
```

Два принципи, з яких випливає решта:

**Модель обирає маршрут, а не пише відповідь.** На виході —
`route_to_refunds_review`, а не «Вибачте, повернемо кошти за 3–5 днів». Це знімає
цілий клас ризиків: вигадану політику компанії, обіцяні строки, юридичні
формулювання. У V1, який такої межі не мав, модель самостійно вирішила видати
$59.99 «per policy for inactive users» — політики, якої не існує.

**Останнє слово за детерміністичним кодом.** Модель дає судження; безпеку, гроші
й право на автовідповідь вирішують прямі `if`. Тому найважливіша логіка
тестується без API-ключа, і поплилий ярлик не міняє маршрут.

## Структура

| Шлях | Що це |
|---|---|
| `nebula_triage/taxonomy.py` | 10 категорій, P0–P3, 5 рівнів тону, 10 маршрутів. **Єдине джерело правди**: ті самі рядки формують і схему, і текст промпту, і правила політики |
| `nebula_triage/schema.py` | Pydantic-моделі відповіді для V2 і V3 |
| `nebula_triage/prompts.py` | Три покоління промпту; V1 і V2 живі як контрольна група |
| `nebula_triage/classifier.py` | Єдина точка виклику LLM |
| `nebula_triage/policy.py` | 7 детерміністичних правил маршрутизації |
| `nebula_triage/runner.py` | Прогін набору + метрики + звіти |
| `nebula_triage/cli.py` | CLI |
| `data/tickets.json` | 15 тікетів із golden labels |
| `scripts/eval_prompts.py` | Порівняння V1/V2/V3 |
| `scripts/stability_check.py` | Повторюваність V3 на N прогонів |
| `scripts/test_policy.py` | 11 офлайн-перевірок політики |
| `results/` | Сирі відповіді моделі з усіх прогонів, зокрема ті, що цитуються в документації |

## Обмеження

- **Датасет синтетичний.** 15 тікетів, написаних і розмічених однією людиною,
  яка знала, що тестує. Перед продакшеном потрібні 200–500 реальних тікетів і
  щонайменше два незалежні анотатори.
- **Пороги впевненості (0.75 / 0.85) — стартові припущення**, не висновок із
  даних. `docs/automation-boundaries.md` описує, як їх калібрувати.
- **Немає детермінізму.** Sonnet 5 відхиляє `temperature`. Дисперсія виміряна
  (`results/stability_v3.md`), а не проігнорована.
- **Кешування промпту не ввімкнене.** Розрахунок економії є в
  `docs/architecture.md`; без реального трафіку перевірити hit rate неможливо.
- **Review-черга описана, але не збудована** — завдання просить механізм, не
  фронтенд.
