# Nebula — AI-класифікатор звернень підтримки

Прототип системи, яка приймає текст тікета і повертає **категорію**, **пріоритет**
і **рекомендований наступний крок** — плюс рішення про те, чи можна цей тікет
обробляти без людини.

Тестове завдання на позицію AI Ops Specialist.

---

## Швидкий старт

```bash
python3 -m venv .venv && .venv/bin/pip install -r requirements.txt
cp .env.example .env    # вписати ANTHROPIC_API_KEY
```

Windows (PowerShell) — далі в усіх командах замініть `.venv/bin/python` на
`.venv\Scripts\python`:

```powershell
python -m venv .venv; .venv\Scripts\pip install -r requirements.txt
copy .env.example .env
```

Один тікет:

```bash
.venv/bin/python -m nebula_triage.cli "My subscription renewed and I want my money back"
```

```
category      : refund_request
priority      : P1
next step     : route_to_refunds_review
handling      : HUMAN REVIEW REQUIRED
sentiment     : frustrated   confidence: 0.85   language: en
reasoning     : User explicitly requests a refund for an unwanted auto-renewal charge.
policy rules  : refund_needs_human
  -> refund decisions are made by a person, never by the model
```

| Команда | Що робить | Ціна |
|---|---|---|
| `python -m nebula_triage.cli --dataset data/tickets.json` | прогін 15 тікетів, таблиця `input → expected → actual → pass/fail` | $0.05 |
| `python scripts/eval_prompts.py` | порівняння трьох поколінь промпту | $0.15 |
| `python scripts/compare_models.py` | Haiku vs Sonnet vs Opus: якість, швидкість, вартість | $0.50 |
| `python scripts/stability_check.py --runs 3` | повторюваність V3 | $0.15 |
| `python scripts/test_policy.py` | 12 перевірок політики — **без ключа й без мережі** | $0 |
| `python -m nebula_triage.cli --show-prompt --version v3` | розгорнутий текст промпту | $0 |

## Результати

### Еволюція промпту

`claude-sonnet-5`, 15 тікетів (7 із них edge cases):

| метрика | V1 наївний | V2 зі схемою | V3 фінальний |
|---|---|---|---|
| точність категорії | 7% | 93% | **100%** |
| точність пріоритету | 40% | 87% | **100%** |
| точність review-гейта | 33% | 87% | **100%** |
| safety recall | **0%** | 100% | 100% |
| стійкість до prompt injection | так | так | так |
| виходів поза схемою | **29** | 0 | 0 |

Стабільність V3 на трьох повторних прогонах: **14/15 тікетів ідентичні**,
категорія, пріоритет і safety recall — 100% у кожному.

### Вибір моделі

| | haiku-4-5 | **sonnet-5** | opus-5 |
|---|---|---|---|
| pass rate (усі три поля) | 87% | **100%** | 87% |
| латентність, медіана | 4522 мс | 3906 мс | 3702 мс |
| cache hit rate | **0%** | 98% | 98% |
| **вартість 10k тікетів** | $33.60 | **$32.76** | $62.42 |

**Haiku тут не дешевший.** Його мінімальний кешований префікс — 4096 токенів,
а наш запит має 3488 однакових токенів у префіксі, тож кеш просто не
створюється. Вдвічі нижча ставка не компенсує десятикратної різниці в тому, за
що нараховують. Двоступеневу схему з Haiku на першому проході, яку я пропонував
до вимірювання, довелось зняти.

### Вартість

**$0.00328 за тікет → $32.76 на 10 000 тікетів/місяць.** Кешування системного
промпту і схеми дає трикратну економію ($93 → $33) без жодного впливу на якість.

Уся розробка разом із вимірюваннями коштувала **~$1.67** на API: 19 збережених
прогонів у `results/` плюс поодинокі виклики під час налагодження. Порівняння
трьох моделей, яке спростувало мою власну пропозицію двоступеневої схеми, —
$0.50 з цієї суми. Це наводить на думку, що більшість архітектурних суперечок
про LLM дешевше вирішити виміром, ніж обговоренням.

> 15 синтетичних тікетів, розмічених одним автором, — це доказ працездатності
> підходу, а не оцінка якості. Що саме ці цифри не доводять — в кінці
> `docs/prompt-evolution.md` і `docs/model-comparison.md`.

## Як це працює

```
текст тікета
   │
   ├─ 1. НОРМАЛІЗАЦІЯ — текст загортається в <ticket>…</ticket> як дані, не команди
   │
   ├─ 2. LLM  ← єдине місце, де працює AI
   │     claude-sonnet-5, промпт V3, відповідь через messages.parse() зі схемою
   │     Pydantic: category · secondary_categories · priority · sentiment ·
   │     confidence · language · safety_signal · action · reasoning
   │
   ├─ 3. ВАЛІДАЦІЯ — значення поза словником неможливе на рівні API
   │
   ├─ 4. POLICY  ← звичайний код, без AI; може лише підвищити обережність
   │     safety-сигнал        → людина, P0, крапка
   │     рефанд               → людина, мінімум P1
   │     кілька запитів       → людина
   │     confidence < 0.75    → людина
   │     агресія + шаблон     → людина
   │     збій класифікації    → людина, P2 (тікет не зникає і не вгадується)
   │
   └─ 5. МАРШРУТ у чергу команди, або прапорець на review-чергу з причиною
```

Два принципи, з яких випливає решта:

**Модель обирає маршрут, а не пише відповідь.** На виході —
`route_to_refunds_review`, а не «Вибачте, повернемо кошти за 3–5 днів». У V1, який
такої межі не мав, модель самостійно вирішила видати $59.99 «per policy for
inactive users» — політики, якої не існує.

**Останнє слово за детерміністичним кодом.** Модель дає судження; безпеку, гроші
й право на автовідповідь вирішують прямі `if`. Тому найважливіша логіка
тестується без API-ключа, і поплилий ярлик не міняє маршрут.

## Структура

| Шлях | Що це |
|---|---|
| `nebula_triage/taxonomy.py` | 10 категорій, P0–P3, 5 рівнів тону, 10 маршрутів. **Єдине джерело правди**: ті самі рядки формують і схему, і текст промпту, і правила політики |
| `nebula_triage/schema.py` | Pydantic-моделі відповіді для V2 і V3 |
| `nebula_triage/prompts.py` | Три покоління промпту; V1 і V2 живі як контрольна група |
| `nebula_triage/classifier.py` | Єдина точка виклику LLM; кешування, ретраї, ланцюг обробки помилок |
| `nebula_triage/policy.py` | 7 детерміністичних правил + fallback при збої класифікації |
| `nebula_triage/runner.py` | Прогін, метрики, вартість із урахуванням кешу, звіти |
| `data/tickets.json` | 15 тікетів із golden labels |
| `scripts/` | eval промптів, порівняння моделей, перевірка стабільності, офлайн-тести політики |
| `results/` | Сирі відповіді моделі з усіх прогонів, зокрема ті, що цитуються в документації |

## Обмеження

- **Датасет синтетичний.** 15 тікетів, написаних і розмічених однією людиною,
  яка знала, що тестує. Перед продакшеном потрібні 200–500 реальних тікетів і
  щонайменше два незалежні анотатори.
- **Порівняння моделей — по одному прогону на модель.** Вартість, кеш і
  латентність структурні й відтворюються; точність на 15 тікетах гуляє в межах
  ±7 п.п.
- **Пороги впевненості (0.75 / 0.85) — стартові припущення**, не висновок із
  даних. `docs/automation-boundaries.md` описує, як їх калібрувати.
- **Немає детермінізму.** Sonnet 5 відхиляє `temperature`. Дисперсія виміряна
  (`results/stability_v3.md`), а не проігнорована.
- **Немає circuit breaker, черги повторної обробки та алертів** — розібрано в
  `docs/failure-handling.md`.
- **Review-черга описана, але не збудована** — завдання просить механізм, не
  фронтенд.
